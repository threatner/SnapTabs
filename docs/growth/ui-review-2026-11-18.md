# UI review (2026-11-18)

By a read-only review agent, from 18 screenshots of the v1.10 build (every popup view and state, all of Settings, the welcome page at desktop and phone width) plus the component code. Tags: (from screenshot), (from code), (guess). Builds on [ux-review-2026-11-18.md](ux-review-2026-11-18.md).

**Biggest find (verified):** the "Incognito save warning" setting does nothing. `showIncognitoWarning` is written by Settings and never read; the incognito notice shows whenever the scope is All Windows.

## Quick wins (small, safe)

1. **Toast**: white text on `--warning` fails contrast (~2.2:1, estimate); make text on warning dark or make toasts neutral (`--card` + border + coloured icon); add `role="status" aria-live="polite"`; move from `top: 8px` (covers the header's "N sessions saved") to the bottom.
2. **First save shows two confirmations**: the "Snapshot saved!" toast and the "Saved!" tip. Skip the toast when the first-snapshot tip appears.
3. **Card menu**: remove "Restore Session" (duplicates the visible Restore button); keep Pin / Rename / Delete.
4. **Keyboard and motion**: the "…" button only appears on hover (add `.card:focus-within`); one global `:focus-visible` ring (search and sort remove outlines); `prefers-reduced-motion` should stop the six looping animations.
5. **Card meta**: `|` separators → `·`; dates as "Nov 4" not "11/4/2026"; stop the pulse on the saved "Private" badge (pulsing should only mean recording).
6. **Labels**: `aria-label` + `aria-pressed` on the record button (only a `title` today); `aria-expanded` on the scope button and detail group headers; the duplicate modal needs `aria-modal`, Escape to cancel, focus on "Save anyway".
7. **Rating banner**: "Rate it" is a second filled blue button beside Snapshot; use the tip's secondary style.
8. **Detail header**: trash icon 16px vs 14px pin/rename; red at rest (should be muted, red on hover/confirm); armed state needs "Click again to delete".
9. **Danger zone**: "Clear All Data" only deletes sessions (settings survive): rename "Delete all sessions…", show the count when armed, quiet red text instead of a full-width bordered button.
10. **Wording**: sentence case everywhere ("Storage used", "This window" / "All windows"); "quit Chrome" → "the browser" (Brave/Edge); the import toast says "snapshots" where everything else says "sessions".

## Medium changes

- **A. Shared tokens and primitives**: 9 hand-rolled button variants, 5 copies of the same 28px icon button (Header's is 32px), three different view-title styles (14/600, 14/500, 13/500), radii 4/5/6/8/10/12, `--secondary` = `--muted`, TipBanner and RatingPrompt CSS identical. Proposal: radius tokens (`--r-sm` 4, `--r` 6, `--r-lg` 8, pills 999), type scale 11/12/13/14, `.btn` / `.btn-sm` / `.icon-btn` classes, one `Banner.svelte`.
- **B. Recording state**: two stop controls; Snapshot stays the primary while recording. Proposal: while recording, "Stop & save" is primary, Snapshot secondary, Cancel a muted ghost button, record toggle hidden.
- **C. Detail header crowding**: five controls beside the title truncate it to ~120px. Proposal: row 1 back + title (2 lines) + meta; row 2 Restore + "…" menu (Pin / Rename / Delete, same as cards).
- **D. Settings structure**: ~26 elements, a one-row "Warnings" section whose row does nothing, a colour-only count pill, help cards taller than settings rows. See the layout below.
- **E. Welcome page**: two text columns on desktop (guide card vs numbered steps); on phones the indented option cards leave a ~180px column. Proposal: at ≤480px put the step number inline with the heading and let options span the card; "All are off until you turn them on" → "Off by default. Everything stays on this device."; use the same titles as Settings.

## Proposed Settings layout

Header: ← Settings (version moves to the footer).

**Save automatically** (caption "Off by default. Everything stays on this device.")
- When I quit the browser [toggle]: "Saves all open windows as one session."
- When I close a tab group [toggle]: "Keeps a copy of the group's tabs."
- When I close an incognito window [toggle]: "Saves its tabs before they're gone." (shown only when SnapTabs is allowed in incognito; guess that most users don't)
- Rolling backup [select Off / 5 / 15 / 30 / 60 min]: "Keeps one up-to-date copy of your open tabs in case the browser crashes."

**Saving**
- Ask before saving a duplicate [toggle]: "When your tabs match your last session."
- Never save these sites [chip input]: "Applies to every save, including automatic ones. Subdomains included."

**Restoring**
- Open in a new window [toggle]: "Otherwise tabs open in this window."
- Sleep restored tabs [toggle]: "Background tabs load when you click them. Saves memory."
- Incognito tabs open in an incognito window [toggle] (same visibility gate)
- Delete a session after restoring it [toggle]: "Pinned ones too."

**Storage & data**
- Keep up to [N] sessions: "When full, the oldest automatic saves go first. Pinned sessions stay."
- One line: "11 KB of 10 MB used" with a thin bar
- [Export] [Import] + hint
- "Delete all sessions…" as quiet red text

**Help** (plain rows with ↗): How to use SnapTabs · Rate SnapTabs · Report a problem or suggest a feature

Footer: "SnapTabs 1.10.0".

Result: 4 sections + Help instead of 7 + danger zone; 11 working settings, nothing lost (the no-op toggle goes).

## Keep

Visible Restore on cards; one banner at a time; the empty state's single next step; clean no-results state; inline rename; tab-group chips; collapsible groups in detail; the shared toggle; two-click delete confirm; domain normalisation; welcome replicas of real buttons; pinned on top; the restrained dark oklch palette.
