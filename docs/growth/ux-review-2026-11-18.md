# UX and conveyability review (2026-11-18)

Written by a read-only review agent on 2026-11-18 (nothing was built or run). Tags: (from code), (from screenshot), (seen once) = survey/stats, (guess). Companion: [ASO plan](aso-2026-11-18.md).

The question, in the owner's words: SnapTabs "has a good amount of features, but it's not very easily conveyable to the users".

## Top 5 changes, ranked by impact vs effort

1. **Rework the listing for search (S).** Page views ≈ installs, so the problem is reach (seen once). The name never uses "session manager" or "tab saver" (from code). Two of five gallery images are Settings pages (from screenshot). See the ASO plan.
2. **Restore in one click from the list, and skip tabs that are already open (S-M).** On the main list, Restore lives only in a "…" menu with `opacity: 0` until hover (`SessionCard.svelte`) (from code); the guide itself says "open a saved session and click Restore". `restoreSession` adds tabs to the current window and never checks what's open (from code). Ties to 2 "didn't understand", 2 "didn't restore correctly" and the "skip duplicate tabs" comment (seen once). Change: a visible Restore button on each card; skip URLs already open in the target window; toast "Restored 18 tabs (4 already open)".
3. **Make the save bar explain itself (M).** The widest control is the scope dropdown; the record button is an unlabeled circle (from code, `SnapshotBar.svelte`); a save leaves all tabs open, so the first click seems to do nothing. Change: one full-width "Save 23 tabs" button with a small ▾ menu (This window / All windows / Record new tabs…), and a "Close saved tabs" offer in the toast after saving.
4. **Fix the hidden request to Google (S).** `SessionDetail.svelte` loads favicons from `https://www.google.com/s2/favicons?domain=<host>` (from code), sending saved tabs' hostnames to Google, while the listing says "zero outbound requests". Change: use the saved favicon or a local tile.
5. **Redesign the icon (M).** The glyph is Lucide's "type" icon with a box across it (from code); at 16px it reads as a generic blue square with a T (from screenshot).

## Concept and naming

- Too many user-facing names: Snapshot, Session, Recording, Auto, Backup, "Browser close (recovered)", "(closed group)", Private, Pinned (from code). The verb disagrees across surfaces ("Save your tabs" vs a "Snapshot" button with a camera).
- Proposal: everything is a **session**, the action is **Save**; show where a session came from as a muted meta line ("Saved when you quit", "Backup · every 15 min", "Saved when group closed") instead of badges.
- Default names like `Snapshot - Nov 6, 4:08 PM` say nothing; use top domain plus a count ("github.com +7") or the group name.
- Keep Recording, but move it under the Save ▾ menu.

## Popup layout (400×600)

- Header: drop the GitHub icon (Settings already links to GitHub); keep **?** and the gear.
- Main view: cards carry no actions; the Rolling backup sits second in the list (from screenshot). Pin it below user sessions or show it as a one-line footer.
- Settings: 6 sections, one with a single toggle (from code). Proposed 4: **Save automatically** (quit / incognito close / tab group close / backup), **Saving** (duplicate warning, incognito warning, excluded domains), **Restoring**, **Data & storage**. "Restore private to private" is a removal candidate (guess).
- First run: add a "Turn on save-on-quit" button to the first-snapshot tip; existing users never saw the welcome switches (from code, D06).

## Discoverability

- Never surfaced in the UI: the `st` address-bar search and `Alt+Shift+S` (from code). Show a hint under the search box after 3+ sessions (usage stats already support this).
- Pinning (hover menu), excluded domains, import/export and backup are fine where they are once Settings is regrouped. No tour (D03 stands).

## Icon

Two overlapping tab silhouettes (front solid white, back ~50%), optionally a small "saved" notch/arrow; at 16px drop the back tab and the arrow, ≥2px strokes, ~2px padding; keep the blue but more distinct. Test on light and dark toolbars at real size.

## Store assets and description

Gallery and video: see the ASO plan (both reviews agree on leading with the outcome and replacing the Settings screenshots). The small promo tile's third chip is unreadable at list size (from screenshot). The description's 15 dense feature headers should become: promise → 3-step how it works → safety nets (opt-in) → power features → privacy; cut the Brave service-worker detail to one FAQ line.

## Fine as is

Opt-in automatic saving, local-only storage, no accounts, 5 permissions; the welcome guide and **?** link; one-at-a-time tips; the duplicate-save warning and sleeping restored tabs with their tip; tab-group chips; the session detail layout; the dark theme and popup polish; no tour or notifications.
