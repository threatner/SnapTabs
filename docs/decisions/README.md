# Decision register

Every material choice gets a row. Status says who decided: `User decision YYYY-MM-DD`, `Proposed` (awaiting the user), `Assumed` (made without being able to ask; needs confirming), `Code review YYYY-MM-DD`, `Measured YYYY-MM-DD`, or `Superseded by Dnn`. Replaced rows stay; add a new row instead of editing an old decision. A choice whose reasoning needs more than three sentences gets its own ADR file.

This register starts with v1.10. Earlier choices live in `CHANGELOG.md` and `CLAUDE.md`.

| ID | Decision | Status | Reason / consequence |
| --- | --- | --- | --- |
| D01 | v1.10 onboarding has three parts: a "How SnapTabs works" section on the welcome page, ways to reopen it (popup **?** button and a Settings card), and two one-time popup tips (after the first snapshot, after the first restore). | User decision 2026-11-06 | "Didn't understand how to use it" in uninstall answers and direct feedback. Spec: [onboarding](../onboarding/spec.md). |
| D02 | The guide is the welcome page itself. `welcome.html?from=help` only swaps the heading. | User decision 2026-11-07 (confirmed) | One page to keep accurate. Rejected: a separate guide page (two copies of the same explanation drift apart). |
| D03 | The guide explains only the save → close → restore loop. Other features stay discoverable in the popup and the store listing. | User decision 2026-11-07 (confirmed) | The user asked for a simple page and earlier trimmed the welcome page to essentials (v1.9). Rejected: a full feature tour. |
| D04 | Tips are inline, dismissible cards in the popup, one at a time. A pending tip takes the rating banner's place until dismissed. | User decision 2026-11-07 (confirmed) | Visible where the user is already looking; no new permission. Rejected: toasts (gone after 2.5 s), `chrome.notifications` (new permission, interrupts other tabs). |
| D05 | A tip becomes pending in the service worker at the moment its count goes from 0 to 1, not by checking counts later. | User decision 2026-11-07 (confirmed) | Long-time users whose counts were backfilled in v1.9 never see "your first snapshot" advice. Rejected: "show while count ≤ N" (would show to veterans after backfill). |
| D06 | Nothing opens by itself on update; existing users find the guide through the **?** button or Settings. | User decision 2026-11-07 (confirmed) | Same reasoning as the v1.9 welcome page (only for genuinely new users): unexpected tabs annoy people and invite bad reviews. |
| D07 | `npm run check` is the one command that proves a change is done: docs check, type check, unit tests, build. Browser suites (`test:e2e`, `test:e2e:cdp`) stay separate because they open browser windows; CI runs them. | User decision 2026-11-07 (confirmed) | Gives every session one gate to run before claiming done, as the user's working rules ask. |
| D08 | "Save tab groups when you close them" is a setting, off by default. | User decision 2026-11-18 ("go with your picks") | Nothing is saved automatically without opting in (rule since v1.3.1); people who close groups all day would otherwise get many sessions. Spec: [closed groups](../closed-groups/spec.md). Rejected: on by default. |
| D09 | Re-closing the same group (same name, same tab URLs) replaces its earlier copy. | User decision 2026-11-18 ("go with your picks") | Keeps the list from filling with copies. A different set of tabs is a new session. Rejected: a new session on every close. |
| D10 | Saved closed groups are named "<group name> (closed group)"; a group without a name becomes "Unnamed group (closed group)". | User decision 2026-11-18 ("go with your picks") | Says where the session came from at a glance. Rejected: the bare group name (indistinguishable from manual snapshots). |
| D11 | A close counts only when every tab of the group is removed (not window-closing) within 500 ms; SnapTabs decides 600 ms after Chrome reports the group gone. | Assumed | Real-browser probe: a whole-group close removes all tabs within 11 ms and the group event can arrive before the last tab's; one-by-one closing spreads removals out; ungrouping removes no tabs. Rejected: reading the window cache at close time (held 1 of 3 tabs in the one-by-one case). |
| D12 | The tab → group record is kept in `chrome.storage.session` and removed tabs stay looked-up for 5 s. | Superseded by D13 | The service worker may be asleep when a group closes and wakes with empty memory; tabs leave the window cache on refresh before every removal event is handled. |
| D13 | Simpler: the window cache also records tab ids, and a tab removal looks its tab up there before the cache refreshes; refreshes after removals are delayed 300 ms so a whole close burst is looked up against the pre-close cache. Removal handlers wait for the cache to be reloaded from `chrome.storage.session` when the service worker wakes. | User decision 2026-11-18 ("don't overcomplicate") | No second record of tabs to keep in sync. Replaces D12. |
| D14 | Favicons come only from Chrome's local favicon cache (`/_favicon/`, `favicon` permission); never from google.com or the sites. | User decision 2026-11-18 (approved scope A) | Makes "no outbound requests" true and unblocks the Featured badge. `favicon`'s install warning is superseded by `tabs` (documented). Rejected: keep the Google fallback (leaks hostnames); letter tiles only (loses recognisable icons). Spec: [v1.10 growth](../v1.10-growth/spec.md). |
| D15 | Session cards get a visible Restore button, and restoring into the current window skips URLs already open there (with a count in the toast). No setting. | User decision 2026-11-18 (approved scope A) | Restore was hover-only; duplicates on restore match "didn't restore correctly" answers and the "skip duplicates" request. Rejected: a new setting (more to explain). |
| D16 | Store name "SnapTabs - Save Tabs & Session Manager" and summary "Session manager and tab saver: save all open tabs in one click, restore them later with tab groups intact. Free, no account, local." | User decision 2026-11-18 | ASO research: title keywords decide ranking at this size; SnapTabs ranks for none today. Accepted cost: possible small loss on the old "Save & Restore Browser Tabs" phrase (user: "I think it's fine"). Rejected: "Session Manager & Tab Saver" (less natural), keeping the old name. |
| D17 | Gallery order: outcome, Save/Close/Restore, tab groups, safety nets (all off by default), search; footer "Free - No account - Stays on your device". Small promo tile: icon + "SnapTabs" + "Save tabs. Restore later." | User decision 2026-11-18 (approved scope A) | ASO plan: lead with the outcome, drop both Settings screenshots, make the search-result tile legible at half size. |
